📚 ZED Project Limitations & Architecture (Non-Tech Guide)

Every real-world cybersecurity project has boundaries. Being honest about system limitations is what earns high marks in academic evaluations and project vivas. Here are ZED's 4 core limitations explained in plain English:

1. Post-Exploitation Detection (Not Vulnerability Prevention)
Analogy: A smoke detector in a hallway.
Explanation: ZED does not stop a hacker from finding a bug in website code (like poor input sanitization or outdated Apache versions). Instead, ZED detects what happens after the hacker breaks in (e.g., launching hidden command shells, modifying cron files, or encrypting files).
Limitation: The initial exploit still succeeds momentarily before ZED observes the behavior and kills the process.
2. The "Low & Slow" Stealth Attacker
Analogy: A thief walking at normal speed carrying one notebook every two hours.
Explanation: ZED's Machine Learning and Rule engines look for unusual velocity spikes (e.g. 15 files modified in 2 seconds, 10 failed logins in 5 seconds).
Limitation: If a highly skilled, patient attacker executes actions very slowly over several days and uses standard administrative commands ("Living off the Land"), they may blend into normal background noise.
3. User-Space vs. Kernel-Space Architecture
Analogy: A security guard standing in the lobby vs. a guard who built the building's foundation.
Explanation: Multi-million dollar commercial tools (like CrowdStrike Falcon) install deep inside the operating system kernel (Ring 0 / eBPF). ZED runs in user-space using standard Python libraries (psutil, watchdog).
Limitation: If an attacker gains full root / superuser privileges on the machine, they could theoretically issue a kill -9 against ZED's Python process. Hardening the agent against root tampering is outside the scope of this project.
4. Machine Learning False Positives & Training Quality
Analogy: A guard dog trained only in a quiet room barking when a busy delivery truck arrives.
Explanation: ZED's Isolation Forest model learns what "normal" looks like from baseline activity on the machine.
Limitation: If baseline training occurred while the machine was idle, then a legitimate heavy user task (like running a big software build or copying 5,000 family photos) could deviate from the baseline and trigger a false alarm.
💡 Presentation Tip for Your Teacher: "ZED is designed specifically as a lightweight, 8 GB RAM-friendly, behavior-based EDR that pairs rules with unsupervised machine learning to catch novel zero-day patterns without requiring GPU hardware or expensive cloud licenses."
